# 5. 史诗 (Epics)

## 史诗 1：项目基础与核心管理功能
**目标**：此史诗的目标是搭建起项目完整的前后端技术骨架，配置好开发与测试环境，并交付证书元数据管理的核心API接口。完成此史诗后，我们将拥有一个功能上可用的后端服务。

### 故事 1.1：项目初始化与技术栈集成
* **作为一个** 开发者，**我想要** 一个设置好的、包含前后端模块的Monorepo项目结构，**以便于** 我有一个干净、可立即投入开发的基础环境。
* **验收标准**：
    1. 一个空的 Monorepo 仓库被初始化。
    2. 仓库中包含一个后端模块，使用 **Maven** 和 Spring Boot 2.7.x 进行配置。
    3. 仓库中包含一个前端模块，使用 Vue 3.x 进行配置。
    4. 前后端应用都可以在本地独立启动，用于开发和调试。
    5. 根目录包含一个基础的 `README.md` 文件，说明如何安装依赖和启动项目。

### 故事 1.2：TDD环境与CI流水线基础
* **作为一个** 开发者，**我想要** 配置好测试驱动开发（TDD）所需的环境，以及一个基础的持续集成（CI）流水线，**以便于** 我从项目一开始就能保障代码质量并自动化构建与测试。
* **验收标准**：
    1. 后端模块中集成了JUnit 5等测试框架，并配置好TDD开发流程。
    2. 前端模块中集成了 **Jest** 测试框架。
    3. 代码仓库中配置一个基础的CI脚本（如GitHub Actions），在代码提交时能自动执行前后端的单元测试。
    4. 测试覆盖率工具已集成，并设定了**80%**的目标。

### 故事 1.3：数据库集成与核心领域模型定义
* **作为一个** 开发者，**我想要** 将后端服务与MySQL 8.0数据库成功集成，并定义核心的`Certificate`领域模型，**以便于** 系统能够持久化存储证书数据。
* **验收标准**：
    1. 后端应用能够成功连接到本地的MySQL 8.0数据库。
    2. 在DDD的领域层中定义了`Certificate`实体，包含`domain`, `expiryDate`以及创建和修改的审计字段。
    3. 通过数据库迁移工具（如Flyway/Liquibase）或初始化脚本，在数据库中创建了对应的`certificates`表。
    4. `certificates`表中的`domain`字段被设置为唯一约束，以防止域名重复。

### 故事 1.4：证书元数据CRUD的API端点
* **作为一个** 用户，**我想要** 一套完整的RESTful API来对证书元数据进行增、删、改、查操作，**以便于** 我可以通过接口管理我的所有证书资产。
* **验收标准**：
    1. 提供 `POST /api/certificates` 端点用于**创建**新的证书元数据。
    2. 提供 `GET /api/certificates` 和 `GET /api/certificates/{id}` 端点用于**读取**证书列表和单个证书详情。
    3. 提供 `PUT /api/certificates/{id}` 端点用于**更新**一个已存在的证书元数据。
    4. 提供 `DELETE /api/certificates/{id}` 端点用于**删除**一个证书。
    5. 所有端点都必须返回**统一结构的响应体**。
    6. 所有端点都通过 **Swagger 3.0.x** 进行了清晰的文档化。
    7. 所有CRUD操作都能正确更新`creator`, `createdAt`, `modifier`, `modifiedAt`等审计字段。

## 史诗 2：资产看板与可视化
**目标**：开发核心的资产看板用户界面，允许用户查看、搜索、排序和管理所有证书资产，并能实时了解每个证书的健康状况。

### 故事 2.1：看板基础页面与数据获取
* **作为一个** 用户，**我想要** 一个基础的看板页面，它能从后端获取并展示我的证书列表，**以便于** 我有一个集中的地方来查看我的所有资产。
* **验收标准**：
    1. 在Vue应用中创建一个新的页面路由 `/dashboard`，作为资产看板的主页面。
    2. 页面加载时，自动调用史诗1中创建的 `GET /api/certificates` 接口来获取证书数据。
    3. 获取到的证书列表数据被存储在前端的状态管理器中。
    4. 页面上有一个基础表格，能展示出证书的域名、过期日等核心信息。
    5. 页面需要处理加载（Loading）和错误（Error）状态，例如在API请求失败时给予用户清晰的提示。

### 故事 2.2：证书实时状态计算与展示
* **作为一个** 用户，**我想要** 在看板的列表中看到每个证书的健康状态，这个状态应该是实时计算的，**以便于** 我能快速识别出哪些证书需要立即关注。
* **验收标准**：
    1. 在看板表格中增加"状态"列。
    2. 前端应用根据当前日期和证书的过期日，**实时计算**出其状态（正常、警告、紧急、危险）。
    3. "状态"列需要根据不同的状态显示对应颜色的标签，使其一目了然。
    4. 页面整体风格简洁，并使用"**平安橙**"作为主题强调色。

### 故事 2.3：看板排序与搜索功能
* **作为一个** 用户，**我想要** 对看板上的证书列表进行排序和搜索，**以便于** 我能快速地从大量证书中定位到我需要的信息。
* **验收标准**：
    1. "过期日"列的表头是可点击的，点击后可以按日期进行升序或降序排序。
    2. 页面上提供一个搜索框，允许用户按域名进行模糊搜索。
    3. 排序和搜索功能需要通过调用后端API并传递参数来实现，以确保在大数据量下的性能。

### 故事 2.4：集成证书的增、改、删操作
* **作为一个** 用户，**我想要** 直接在看板页面上发起对证书的增、改、删操作，**以便于** 我的管理工作流程更加高效和连贯。
* **验收标准**：
    1. 看板页面上有一个"新增证书"的按钮，点击后会弹出一个表单模态框，用于提交新证书。
    2. 列表中的每一行都有"编辑"和"删除"按钮。
    3. 点击"编辑"按钮，会弹出同样的表单模态框，并预先填好该证书的现有数据。
    4. 点击"删除"按钮，会有一个二次确认提示，确认后调用删除API。
    5. 在完成任何增、改、删操作后，看板的证书列表会自动刷新，以显示最新数据。
