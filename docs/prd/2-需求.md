# 2. 需求

## 2.1 功能性需求 (FR) - 最终版
* **FR1**: 用户能够对证书元数据（域名、过期日）进行创建、读取、更新和删除（CRUD）操作。
* **FR2**: 系统的所有CRUD操作必须包含审计字段，自动记录创建人、创建时间、修改人和修改时间。
* **FR3**: 用户可以通过一个资产看板查看所有证书的列表，包括域名和其对应的状态标签。状态标签由前端实时计算得出。
* **FR4**: 在资产看板上，用户能够按域名进行模糊搜索。
* **FR5**: 在资产看板上，用户能够按时间（例如，过期日）对证书进行排序。

## 2.2 非功能性需求 (NFR)
* **NFR1**: 后端服务必须使用 Java (JDK 8) 和 Spring Boot (2.7.x) 进行开发。
* **NFR2**: 前端应用必须使用 Vue (3.x) 框架进行开发。
* **NFR3**: 数据存储必须使用 MySQL (8.0) 数据库。
* **NFR4**: 整体系统架构必须遵循DDD（领域驱动设计）分层原则。
* **NFR5**: 为避免数据冲突，证书的域名（`domain`）在数据库层面必须是唯一的。
* **NFR6**: 为保证计算结果的一致性，所有日期相关的计算必须强制使用 UTC+8 时区。
* **NFR7**: 所有API请求都需要记录结构化的日志，包含请求ID、耗时等关键信息，以便于问题排查和性能分析。
